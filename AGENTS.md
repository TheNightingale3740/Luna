# Radiance — AGENTS.md

macOS-only MetalRT path tracer with a C++23 editor app. Premake5 build system, GLFW + ImGui (docking branch) + spdlog + glm + Apple metal-cpp (vendored as submodules).

## Build & Run

```sh
premake5 gmake           # generate Makefiles (run after any premake5.lua change)
make config=debug        # or release, dist
open bin/Debug/RadianceEditor.app
```

`make` builds both `Radiance` (static lib) then `RadianceEditor` (console app). The editor is the only executable target.

## Architecture

- **Entry point**: `Radiance/Source/Radiance/Core/EntryPoint.h` defines `main()`. Consumer apps (like the editor) `#include <Radiance.h>` and implement `Radiance::CreateApplication()` — same pattern as Hazel/Walnut.
- **Editor code**: `RadianceEditor/Source/EditorMain.cpp` — contains `EditorLayer` and `CreateApplication()`.
- **Library namespace**: `Radiance`, organized as `Core/`, `Events/`, `ImGui/`, `Metal/`, `Renderer/`, `Utils/`.
- **Namespaces mirror directory structure** under `Radiance/Source/Radiance/`.

## Shader Compilation (prebuild step)

`CompileShaders.lua` compiles `.metal` files → `.air` → `PathTracingShader.metallib`. Source: `Radiance/Source/Radiance/Renderer/Shaders/`. Output: `Radiance/Source/Radiance/Res/Shaders/`. The `.metallib` is loaded at runtime from the app bundle's `Resources/` dir.

Only one shader file: `PathTacing.metal` (note the typo in filename — "Tacing" not "Tracing").

## Known Bugs (see BUG_ANALYSIS.md)

The codebase has known issues to avoid introducing:
- Metal objects (`MTL::Device`, command queues, drawables, render pass descriptors, `CA::MetalLayer`) are regularly not `->release()`'d — check all `alloc()->init()` and `CreateSystemDefaultDevice()` calls.
- `Application::Get()` returns a reference from a nullable `static s_Application` with no null check — use `&Application::Get()` cautiously.
- `glfwPollEvents()` is called in both `Application::Run()` and `Window::OnUpdate()` — double polling per frame.
- `EventDispatcher::Dispatch` uses `*(T*)&m_Event` C-style cast — don't replicate this pattern.

## Conventions

- C++23, macOS arm64 only.
- Header-only `EntryPoint.h` pattern — don't add a second `main()`.
- `.mm` files for ObjC++ (Metal, ImGui backends).
- Vendor libs are git submodules; `glfw` binary is checked in as `Radiance/Vendor/glfw/lib/libglfw3.a`.
- `Info.plist` and `PkgInfo` are generated by `GeneratePlist.lua` in prebuild.
- No CI, no tests, no linter/formatter config.
